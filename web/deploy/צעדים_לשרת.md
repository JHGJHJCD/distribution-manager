# התקנת האתר בשרת — צעדים

למי שמבצע (הסוכן שבשרת, או יהודה): לבצע לפי הסדר, ולעצור בכל שלב שהבדיקה שלו לא עוברת.
**שום דבר מכאן לא נוגע בשירותים שכבר רצים בשרת** (אוצריא, הפורום, גשר ה-SSH): משתמש נפרד, תיקייה נפרדת, פורט נפרד (8787).
**כתובות, סיסמאות ומפתחות לא נכנסים לגיט ולא לצ'אט.** המאגר ציבורי.

בשלב הזה עולה האתר **עם אנשים מומצאים בלבד**. הנתונים האמיתיים עוברים רק בסוף, בצעד נפרד (למטה).

## 1. משתמש ותיקיות
```
sudo useradd --system --home /opt/haluka --shell /usr/sbin/nologin haluka
sudo mkdir -p /opt/haluka/data /etc/haluka
sudo git clone https://github.com/JHGJHJCD/distribution-manager.git /opt/haluka/app
sudo python3 -m venv /opt/haluka/venv
sudo /opt/haluka/venv/bin/pip install -r /opt/haluka/app/web/deploy/requirements.txt
sudo chown -R haluka:haluka /opt/haluka/data
sudo chmod 700 /opt/haluka/data
```

## 2. הגדרות
```
sudo cp /opt/haluka/app/web/deploy/web.env.example /etc/haluka/web.env
sudo chmod 600 /etc/haluka/web.env
```
לערוך את `/etc/haluka/web.env`: למלא את `HALUKA_WEB_HOSTS` בשם שבו האתר ייפתח (ראה צעד 5).

## 3. נתונים מומצאים לבדיקה, וסיסמאות
```
cd /opt/haluka/app
sudo -u haluka PYTHONUTF8=1 /opt/haluka/venv/bin/python web/tests/demo_data.py /opt/haluka/data
```
סיסמאות: **יהודה מקליד אותן בעצמו** (הן לא מוצגות ולא נשמרות, רק ה-hash). לפחות 8 תווים.
```
sudo -u haluka env HALUKA_WEB_DATA=/opt/haluka/data /opt/haluka/venv/bin/python -m web.auth set יהודה
sudo -u haluka env HALUKA_WEB_DATA=/opt/haluka/data /opt/haluka/venv/bin/python -m web.auth set רון
```

## 4. השירות
```
sudo cp /opt/haluka/app/web/deploy/haluka-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now haluka-web
curl -s http://127.0.0.1:8787/healthz          # צריך לענות {"ok":true}
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: <השם מצעד 2>" http://127.0.0.1:8787/api/people   # צריך לענות 401
```
בדיקת מוכנות (לא מדפיסה שמות ולא כתובות; `FAIL` = לא פותחים את האתר):
```
sudo -u haluka bash -c 'set -a; . /etc/haluka/web.env; set +a; cd /opt/haluka/app; /opt/haluka/venv/bin/python -m web.server_check'
```

## 5. החיבור מבחוץ (מנהרה)
האתר מקשיב רק ל-127.0.0.1:8787. מבחוץ מגיעים אליו דרך מנהרת cloudflared, כמו בשירותים האחרים בשרת. **חומת האש לא משתנה.**
- **עדיף: שם קבוע** (מנהרה עם שם, או נתיב ב-Worker הקיים). אז `HALUKA_WEB_HOSTS` = השם הקבוע.
- מנהרה זמנית (הכתובת מתחלפת בכל הפעלה): `HALUKA_WEB_HOSTS=*.trycloudflare.com`. אם הגלישה עוברת דרך Worker קבוע, לוודא שהוא מעביר את הבקשה כמו שהיא: נתיב, גוף, כותרות (כולל `X-Haluka` ו-`Cookie`) ואת `Set-Cookie` בתשובה.
- החיבור חייב להיות https: בלי זה הדפדפן לא שומר את הכניסה (כך זה בנוי בכוונה).
- בדיקה: לפתוח את הכתובת בדפדפן ← מסך כניסה ← להיכנס ← רואים את השבועות ואת "יציאה" ← לצאת ← שוב מסך כניסה.

## 6. גיבוי שיוצא מהשרת (אחרי שיהודה מחליט לאן)
למלא ב-`/etc/haluka/web.env` את `HALUKA_OFFSITE_DIR` או את `HALUKA_OFFSITE_CMD`, ואז:
```
sudo cp /opt/haluka/app/web/deploy/haluka-offsite.* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now haluka-offsite.timer
sudo systemctl start haluka-offsite && systemctl status haluka-offsite --no-pager | tail -3
```
בקובץ יש טלפונים: היעד חייב להיות פרטי, ומוצפן אם הוא לא שלנו (למשל `rclone` עם `crypt`).
במסך ההגדרות, תחת "גיבוי ושחזור", כתוב מתי יצא העותק האחרון, ומופיעה אזהרה אם יומיים לא יצא.

## 7. עדכון גרסה
```
cd /opt/haluka/app && sudo git pull && sudo systemctl restart haluka-web
```

## 8. בסוף, אחרי שהכול יציב: הנתונים האמיתיים
רק באישור מפורש של יהודה. מעתיקים את קובץ הנתונים של האתר ממחשב של יהודה ל-`/opt/haluka/data/haluka.db` (בעלים `haluka`, הרשאה 600) בחיבור מוצפן, מפעילים מחדש, ומריצים שוב את בדיקת המוכנות. מאותו רגע הגיבוי שיוצא מהשרת חייב לעבוד (צעד 6).
