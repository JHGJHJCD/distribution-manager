# התקנת האתר בשרת — צעדים

למי שמבצע (הסוכן שבשרת, או יהודה): לבצע לפי הסדר, ולעצור בכל שלב שהבדיקה שלו לא עוברת.
**שום דבר מכאן לא נוגע בשירותים שכבר רצים בשרת** (אוצריא, הפורום, גשר ה-SSH): משתמש נפרד, תיקייה נפרדת, פורט נפרד (8787).
**כתובות, סיסמאות ומפתחות לא נכנסים לגיט ולא לצ'אט.** המאגר ציבורי.

בשלב הזה עולה האתר **עם אנשים מומצאים בלבד**. הנתונים האמיתיים עוברים רק בסוף, בצעד נפרד (למטה).

## 1. משתמש ותיקיות
```
sudo useradd --system --home /opt/haluka --shell /usr/sbin/nologin haluka
sudo mkdir -p /opt/haluka/data /etc/haluka
sudo git clone https://github.com/JHGJHJCD/distribution-manager.git /opt/haluka/app
sudo python3 -m venv /opt/haluka/venv
sudo /opt/haluka/venv/bin/pip install -r /opt/haluka/app/web/deploy/requirements.txt
sudo chown -R haluka:haluka /opt/haluka/data
sudo chmod 700 /opt/haluka/data
```

## 2. הגדרות
```
sudo cp /opt/haluka/app/web/deploy/web.env.example /etc/haluka/web.env
sudo chmod 600 /etc/haluka/web.env
```
לערוך את `/etc/haluka/web.env`: למלא את `HALUKA_WEB_HOSTS` בשם שבו האתר ייפתח (ראה צעד 5).

## 3. נתונים מומצאים לבדיקה, וסיסמאות
```
cd /opt/haluka/app
sudo -u haluka PYTHONUTF8=1 /opt/haluka/venv/bin/python web/tests/demo_data.py /opt/haluka/data
```
**מי נכנס (הכרעת יהודה 26/11: כניסה עם חשבון Google).** מאשרים את כתובות המייל של יהודה ושל רון:
```
sudo -u haluka env HALUKA_WEB_DATA=/opt/haluka/data /opt/haluka/venv/bin/python -m web.auth allow <כתובת המייל> יהודה
sudo -u haluka env HALUKA_WEB_DATA=/opt/haluka/data /opt/haluka/venv/bin/python -m web.auth allow <כתובת המייל> רון
```
(`disallow <כתובת>` מוציא מיד; `list` מציג. כניסה עם שם וסיסמה קיימת רק אם מגדירים `set <שם>`; לא צריך.)

### 3א. הגדרה חד-פעמית אצל Google (יהודה, בדפדפן: console.cloud.google.com)
1. פרויקט (אפשר הקיים של התוכנה) ← "APIs & Services" ← להפעיל את **Google Drive API**.
2. "OAuth consent screen": סוג External; ההרשאות (scopes): `openid`, `email`, `drive.file` בלבד. **לפרסם את האפליקציה ("In production")**: במצב "Testing" החיבור ל-Drive פג אחרי שבוע.
3. "Credentials" ← Create ← OAuth client ID ← **Web application**. ב-"Authorized redirect URIs" שתי כתובות:
   `https://<שם האתר>/auth/google/callback` ו-`https://<שם האתר>/auth/drive/callback`.
4. את ה-Client ID וה-Client secret כותבים ב-`/etc/haluka/web.env` (`HALUKA_GOOGLE_CLIENT_ID`, `HALUKA_GOOGLE_CLIENT_SECRET`), יחד עם `HALUKA_WEB_URL=https://<שם האתר>`. **לא בצ'אט ולא בגיט.**

## 4. השירות
```
sudo cp /opt/haluka/app/web/deploy/haluka-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now haluka-web
curl -s http://127.0.0.1:8787/healthz          # צריך לענות {"ok":true}
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: <השם מצעד 2>" http://127.0.0.1:8787/api/people   # צריך לענות 401
```
בדיקת מוכנות (לא מדפיסה שמות ולא כתובות; `FAIL` = לא פותחים את האתר):
```
sudo -u haluka bash -c 'set -a; . /etc/haluka/web.env; set +a; cd /opt/haluka/app; /opt/haluka/venv/bin/python -m web.server_check'
```

## 5. החיבור מבחוץ (מנהרה)
האתר מקשיב רק ל-127.0.0.1:8787. מבחוץ מגיעים אליו דרך מנהרת cloudflared, כמו בשירותים האחרים בשרת. **חומת האש לא משתנה.**
- **אין דומיין (התברר 26/11), ויהודה בחר בדרך החינמית:** כתובת קבועה `workers.dev` שמעבירה למנהרה זמנית.
  1. ב-Cloudflare: ליצור Worker חדש (למשל `haluka`) עם הקוד של `web/deploy/worker.js`; לקשור אליו KV namespace בשם `HALUKA_KV`; ולהגדיר שני סודות: `HALUKA_PROXY_SECRET` ו-`HALUKA_REGISTER_KEY` (שני טקסטים אקראיים ארוכים, למשל `openssl rand -hex 32`).
  2. ב-`/etc/haluka/web.env`: `HALUKA_WEB_HOSTS=*.trycloudflare.com`, `HALUKA_WEB_URL=https://<כתובת ה-Worker>`, ו-`HALUKA_PROXY_SECRET` (אותו טקסט כמו ב-Worker). ואז `sudo systemctl restart haluka-web`.
  3. `/etc/haluka/tunnel.env` (הרשאה 600, בעלים haluka): `HALUKA_FRONT_URL=https://<כתובת ה-Worker>` ו-`HALUKA_REGISTER_KEY=<הסוד>`.
  4. `sudo cp /opt/haluka/app/web/deploy/haluka-tunnel.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now haluka-tunnel`
  5. בדיקה: `curl -s -o /dev/null -w "%{http_code}\n" https://<כתובת ה-Worker>/login` ← 200; ואותה בקשה ישר לכתובת ה-`trycloudflare.com` ← 403 (רק ה-Worker מגיע לאתר).
- אצל Google (צעד 3א) כתובות החזרה הן על כתובת ה-Worker. **לא נבדק** ש-Google מקבל כתובת `workers.dev`; אם הוא מסרב, לעצור ולדווח.
- אם יהיה פעם דומיין: מנהרה עם שם, `HALUKA_WEB_HOSTS` = השם, ובלי ה-Worker ובלי `HALUKA_PROXY_SECRET`.
- החיבור חייב להיות https: בלי זה הדפדפן לא שומר את הכניסה (כך זה בנוי בכוונה).
- בדיקה: לפתוח את הכתובת בדפדפן ← מסך כניסה ← להיכנס ← רואים את השבועות ואת "יציאה" ← לצאת ← שוב מסך כניסה.

## 6. גיבוי שיוצא מהשרת (אחרי שיהודה מחליט לאן)
**הכרעת יהודה 26/11: Google Drive מוצפן, שמחברים מהאתר.** יהודה נכנס לאתר ← הגדרות ← "גיבוי ושחזור" ← "חבר ל-Google Drive", מאשר אצל Google, ו**שומר את מפתח השחזור שמוצג פעם אחת** (בלי המפתח אי אפשר לפתוח אף גיבוי). אחר כך מפעילים את השעון היומי:
```
sudo cp /opt/haluka/app/web/deploy/haluka-offsite.* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now haluka-offsite.timer
sudo systemctl start haluka-offsite && systemctl status haluka-offsite --no-pager | tail -3
```
כל עותק מוצפן בשרת לפני שהוא יוצא; האתר רואה ב-Drive רק את הקבצים שהוא עצמו שם שם (התיקייה "גיבוי מנהל חלוקה").
פתיחת גיבוי שהורד מה-Drive, בכל מחשב: `python -m web.drive open <קובץ.enc> <קובץ-חדש.db>` (מבקש את המפתח).
(חלופה בלי Drive: `HALUKA_OFFSITE_DIR` או `HALUKA_OFFSITE_CMD` ב-`web.env`; הן קודמות ל-Drive.)
במסך ההגדרות, תחת "גיבוי ושחזור", כתוב מתי יצא העותק האחרון, ומופיעה אזהרה אם יומיים לא יצא.

## 7. עדכון גרסה
```
cd /opt/haluka/app && sudo git pull && sudo systemctl restart haluka-web
```

## 8. בסוף, אחרי שהכול יציב: הנתונים האמיתיים
רק באישור מפורש של יהודה. מעתיקים את קובץ הנתונים של האתר ממחשב של יהודה ל-`/opt/haluka/data/haluka.db` (בעלים `haluka`, הרשאה 600) בחיבור מוצפן, מפעילים מחדש, ומריצים שוב את בדיקת המוכנות. מאותו רגע הגיבוי שיוצא מהשרת חייב לעבוד (צעד 6).
