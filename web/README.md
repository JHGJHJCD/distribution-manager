# האתר של מנהל חלוקה (`web/`)

גרסת אתר של התוכנה: רצה קודם על המחשב הזה בלבד, ובהמשך עוברת כמו שהיא לשרת.
הכרעות: `docs/plans/אתר_תכנון_מצב.md` · שלבי הבנייה: `docs/plans/אתר_תוכנית.html` · יומן וסטיות: `web/implementation-notes.md`.

## הרעיון
העבר קבוע, העתיד מחושב תמיד מחדש. נשמרים רק כרטיסים, היסטוריה והגדרות; רשימה של שבוע שעוד לא הגיע לא נשמרת בשום מקום.
מי מקבל נקבע ב-`selection.py` / `scoring.py` / `holidays.py` שבשורש המאגר, בלי שום שינוי בהם.

## הפעלה (מקומית)
לחיצה כפולה על `web\run_local.bat` פותחת את האתר בדפדפן: http://127.0.0.1:8787
סגירת החלון השחור עוצרת אותו. האתר עונה רק למחשב הזה.

## קבצים
- `planner.py` — החישוב קדימה (טהור: בלי מאגר, בלי שעון): שבועות ואירועי חג על אותו ציר זמן (`plan_timeline`). `engine.py` — הכניסה היחידה למנוע הכללים.
- `store.py` — המאגר של האתר (SQLite). `service.py` — איזה שבוע הוא "עכשיו", סגירת שבועות שעברו, התשובות לדפים.
- `cards.py` — הכללים של כרטיס מקבל (טהור): שם "משפחה פרטי", סטטוס, שמונת הסוגים, "נתמך חגים", חיפוש, כרטיסים שנראים כפולים, מיזוג. `card_service.py` — התשובות של מסך המקבלים.
- `event_service.py` — חלוקות חג (שלב 4): האירועים שלפנינו, אירוע אחד במלואו, יצירה / שינוי / מחיקה, שינויים ביד, דף ההדפסה והאקסל של אירוע.
- `app.py` — הנתיבים. `config.py` — תיקיית הנתונים, שעון ישראל, ברירות מחדל.
- `static/` — הדפים: `index.html` + `app.js` + `style.css` (מסך השבועות), `people.html` + `people.js` (מסך המקבלים), `common.js` (משותף), `print.html` + `print.js` + `print.css` (דף ההדפסה, עמוד A4 לכל שבוע).
- `import_old.py` — ייבוא חד-פעמי מ**עותק** של `data.db` של התוכנה הישנה.
- `data/` — הנתונים והגיבויים. **נתונים אישיים; מוחרג מגיט; לא להעלות לשום מקום.**

## מה אפשר לעשות במסך (שלב 2)
- לשבוע שנבחר: לשנות את מספר המנות והרזרבה, ולחזור למספרים הרגילים.
- לחיצה על שם (או חיפוש): הסבר במשפט, ומתחתיו כפתורים — להעביר לרזרבה, להסיר מהשבוע, להכניס לרשימה, להוסיף לשבוע, ולבטל שינוי ביד. מי שנקבע ביד מסומן ✋.
- "הדפס" / "אקסל": לשבוע שנבחר ולכמה שבועות אחריו. שבוע שהשתנה אחרי שהודפס מסומן ⚠, עם "השתנה מאז ההדפסה: נוסף X, יצא Y".
- שינוי ביד נשמר לשבוע שלו בלבד. רשימה עתידית עדיין לא נשמרת: היא מחושבת כל פעם, יחד עם מה שנקבע ביד.

## מסך המקבלים (שלב 3) — `/people`
- רשימה עם חיפוש (שם, טלפון, כתובת) וסינון פעילים / מושהים. לחיצה על שורה פותחת כרטיס.
- כרטיס: עריכה, "מתי יקבל" בשבועות הקרובים, "השהה" / "החזר לפעיל", ו"מחק" (רק לכרטיס שלא קיבל אף פעם; אפשר לבטל, ויש "כרטיסים שנמחקו").
- "+ מקבל חדש": אם כבר יש כרטיס עם אותו שם או טלפון, שואלים קודם; ברירת המחדל "שני אנשים שונים".
- "כרטיסים שנראים כפולים": הצעות בלבד. "אנשים שונים" מעלים את ההצעה; "השווה ומזג…" מראה את שני הכרטיסים זה ליד זה, ורק אז אפשר למזג.

## חלוקת חג (שלב 4)
- אירוע חג הוא סיבוב נוסף שהמנהל קובע: תאריך, לאיזה חג, מספר מנות, רזרבה, וסינון (ילדים / הכנסה / פנוי לנפש, "מ-" ו"עד").
- ברשימה: כל כרטיס פעיל שמסומן "נתמך חגים" לחג הזה ועובר את הסינון, בלי קשר לסוג ולתור. חסר נתון בשדה שמסננים לפיו = לא נכנס, ומוצג בנפרד. בחוסר מנות: מי שמחכה הכי הרבה זמן. הרזרבה: רק הבאים בתור מאותה רשימה.
- **חג לא נספר ברשימות הרגילות** (הכרעת יהודה 26/11/2026): האירוע לא מזיז את התור של קבוע, חד-פעמי שקיבל בו לא נכנס להפסקה, וזמן ההמתנה ברשימה רגילה נמדד מהחלוקה הרגילה האחרונה. השבועות נראים בדיוק אותו דבר עם האירוע ובלעדיו.
- האירוע מחושב יחד עם השבועות לפי סדר התאריכים (אירוע ביום רביעי: אחרי הרשימה הרגילה של אותו יום), ונכתב להיסטוריה ב-06:00 בבוקר שאחרי היום שלו.
- שינויים ביד, הדפסה, אקסל ו"השתנה מאז ההדפסה" עובדים כמו בשבוע.
- **המסך (`/holiday`):** רשימת האירועים שלפנינו, אירועים שעברו (לקריאה בלבד) ואירועים שנמחקו. אירוע חדש נשמר רק בלחיצה על "צור את החלוקה"; באירוע קיים כל שינוי בשדה נשמר לבד. "מחק את החלוקה" לא מוחק באמת: אפשר להחזיר את האירוע, עם כל מה שנקבע בו, כל עוד היום שלו לא עבר. אירוע שעתיד לקרות מופיע גם ברצועת השבועות, במקום שבו הוא נופל.

## כללים
- כל כתיבה לשרת היא `POST` עם הכותרת `X-Haluka: 1` (בלי הכותרת: 403). הדפים שולחים אותה בעצמם.
- טלפונים יוצאים מהשרת רק ב-`/api/print`, בקובץ האקסל (שניהם לטווח שבועות או לאירוע חג אחד), ובכרטיס אחד שנפתח (`/api/card`, `/api/duplicates/compare`); התשובות של מסך השבועות, מסך החג, רשימת המקבלים, החיפוש וההצעות לכפילויות בלי טלפונים.
- הכללים של כרטיס נמצאים ב-`cards.py` בלבד; שום דבר לא ממזג כרטיסים בלי בקשה מפורשת לזוג מסוים.
- בדפים אין משאבים חיצוניים ואין קוד או עיצוב בתוך ה-HTML (יש CSP); טקסט מהנתונים נכנס לדף רק עם `textContent`.
- שום קובץ ב-`web/` לא מייבא את `database.py` (רק הבדיקות, כסרגל להשוואה ובתיקייה זמנית).
- כלל חדש של "מי מקבל" נכנס ל-`selection.py` עם בדיקה שם, לא ל-`planner.py`.
- בבדיקות יש רק אנשים מומצאים. שמות אמיתיים לא נכנסים למאגר הקוד.

## בדיקות (Python 3.12)
```
python web/tests/run_all.py            # כל הבדיקות של האתר
python web/tests/mutation_check.py     # שוברים בכוונה את החישוב, המאגר והנתיבים: הבדיקות חייבות להיכשל
python web/tests/mutation_vs_old.py    # אותו דבר להשוואה מול התוכנה הישנה
python web/tests/local_check_real.py --from <עותק data.db> [--sent-history <json>]   # השוואה על עותק של נתונים אמיתיים, מדפיס מספרים בלבד
```

הבדיקות רצות גם ב-Python 3.11 ומעלה בלינוקס: `pip install fastapi uvicorn openpyxl httpx hypothesis`.
כדי לראות את המסך בלי הנתונים האמיתיים: `python web/tests/demo_data.py <תיקייה ריקה>` בונה מאגר של אנשים מומצאים, ומפנים אליו עם `HALUKA_WEB_DATA`.

## ייבוא נתונים
```
python -m web.import_old --from <עותק של data.db> [--sent-history <sent_history.json>] [--replace]
```
המקור נפתח לקריאה בלבד. `--replace` מגבה קודם את המאגר הקיים של האתר. הדוח שמודפס מכיל מספרים בלבד.
