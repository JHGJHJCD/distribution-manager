# בודק באגים — נקודה אחת, עד הסוף

מטרה: לקחת **נקודה אחת** בתוכנה (פונקציה / כפתור / זרימה / כלל עסקי) ולחפור עליה עמוק עד שבטוחים שאין בה
באגים — ואת מה שנמצא **לתקן מיד**, לאמת ולשחרר. עומק על פני רוחב: לא סקירה כללית של מסך.

הנקודה לבדיקה: **$ARGUMENTS**

## שלב 0 — מה בודקים
- `$ARGUMENTS` ריק/עמום → **שאלה ממוקדת אחת** (AskUserQuestion, עברית מדוברת, "(מומלץ)" בעברית) עם 3–4 נקודות
  קונקרטיות לבחירה (למשל: "מי נכנס לרשימת השבוע", "שמירת חלוקה ורישום מי קיבל", "ייבוא מקבלים מאקסל",
  "גיבוי ושחזור"). **לא לסרוק את כל הפרויקט כדי להחליט.**
- הנקודה שייכת לצינתוקים → לעבוד דרך הסקיל `tzintuk-check`; למיילים → `mail-check` (הם כבר מכילים את הגדרות
  והאינווריאנטים). כלל מי-מקבל → `selection-rule`; סכימה/סנכרון → `db-migration`. תמיד לטעון `manhal-haluka`.
- הגדר במשפט אחד **מה ההבטחה** של הנקודה ("מי שסומן קבוע-שבועי מופיע בכל רביעי, פעם אחת, ולא אחר").
  כל באג = הפרה של ההבטחה הזו.

## שלב 1 — מיפוי (קריאה בלבד)
1. מצא את נקודת-הכניסה וקרא אותה **במלואה**, ואחריה כל פונקציה שהיא קוראת — עד ה-DB / הקובץ / הרשת.
2. `grep` לכל מי ש**קורא** לה (tabs/, utils/, main.py, database.py, test_*.py, dev/) — באג חי לפעמים אצל הקורא.
3. רשום: קלטים (ומאיפה מגיעים — משתמש / אקסל / המחשב השני / שרת), פלטים, מצב שנכתב (DB, settings,
   sync journal, קבצים), והנחות סמויות ("הרשימה לא ריקה", "התאריך תקין", "id מקומי = אותו אדם").
4. בדוק ב-`git log -S`/CLAUDE.md אם כבר תוקנו כאן באגים — כדי לא להחזיר אותם, וכדי לדעת איפה הקוד שביר.

## שלב 2 — ציד (לעבור על **כל** הרשימה, לכתוב ממצא או "נקי" לכל סעיף)
- **ערכי-קצה:** ריק / None / 0 / שלילי / ענק · מחרוזת עם רווחים, גרשיים, אימוג'י, RTL/LRM · מספר כטקסט
  ("4,500 ₪") · תאריך ריק / שבור / עתידי / פורמט אחר · רשימה ריקה / פריט יחיד / כפולים / 500+.
- **זמן:** היום רביעי / לא רביעי · חצות · מעבר שעון קיץ-חורף · שעון ישראל מול UTC · שעון מחשב מפגר · סוף חודש/שנה.
- **מצב:** פעולה פעמיים ברצף (לחיצה כפולה) · ביטול באמצע · סגירת התוכנה באמצע · רענון/סנכרון נכנס בזמן
  שהמשתמש עורך · שורות מוסתרות ע"י סינון · מצב שנשאר מהפעולה הקודמת ולא התאפס.
- **שני מחשבים:** id מקומי מול guid · LWW עם חותם עתידי/שווה · הגדרה שמסונכרנת ולא אמורה (ולהפך) ·
  מחיקה במחשב אחד ועריכה בשני · מחשב שהיה מנותק שבוע.
- **נתונים:** כתיבה חלקית בלי טרנזקציה · חריגה באמצע לולאה שמשאירה חצי-עבודה · מחיקה בלי גיבוי ·
  שדה מוסתר שמתאפס בשמירה · מיגרציה על DB ישן · שאילתה עם LIMIT/ORDER שגוי.
- **שגיאות:** `except` רחב שבולע · הודעה גולמית באנגלית למשתמש · רשת מתה / נטפרי 418 / timeout ·
  קובץ נעול / חסר / 0 בייט · קריאה חוסמת ב-thread של ה-UI.
- **Qt:** signal שיורה בזמן repopulate (בלי `blockSignals`) · ווידג'ט שנמחק ועדיין מוחזק · `selectRow`
  במקום `setCurrentCell` · נגיעה בווידג'ט מ-thread אחר · קומבו ישן בתא טבלה.
- **עקביות:** אותו חישוב בשני מקומות עם תוצאה שונה (מסך מול הדפסה מול אקסל מול היסטוריה) ·
  מונה שלא תואם לרשימה · תיעוד ב-CLAUDE.md שסותר את הקוד.

לכל חשד: **לא להסתפק בקריאה — להריץ.** סקריפט קצר על DB זמני (scratchpad / `tempfile`, **לעולם לא ה-DB האמיתי**,
בלי רשת אמיתית, בלי חיוג/שליחה) שמשחזר את התרחיש. חשד שלא שוחזר = לא באג; לרשום כ"נבדק, תקין".

## שלב 3 — תיקון מיידי
לכל באג שהוכח, לפי הסדר **שלמות נתונים → כללים עסקיים → יציבות → חוויית משתמש → איכות קוד**:
1. **בדיקה שנכשלת קודם** — להוסיף ל-`test_*.py` המתאים (באותו סגנון של הקובץ) ולראות אותה נכשלת.
2. תיקון **בשורש**, לא פלסטר אצל הקורא; לוגיקה במודול הטהור (`selection`/`scoring`/`database`/`utils`), לא בלשונית.
   לפי `feature-impact` — מה התיקון עצמו יכול לשבור (call sites, סנכרון, תאימות לאחור, בדיקות/לינטים).
3. לראות את הבדיקה עוברת. לחפש **את אותו דפוס-באג במקומות אחרים** (`grep`) ולתקן גם שם.
4. מה **לא** מתקנים לבד: דבר שהוא הכרעה עסקית (שני פירושים סבירים לכלל), או "הכרעת המשתמש — לא באג" שכתובה
   ב-CLAUDE.md. את אלה לאסוף ל**סבב שאלות אחד** בסוף (AskUserQuestion) — ובינתיים להמשיך בשאר.

## שלב 4 — אימות ושחרור
1. הבדיקות של האזור + `test_all.py` (Python 3.12, כל קובץ `python test_X.py`); אם נגעת בצינתוקים/מיילים — הבודק שלהם.
2. נגעת ב-UI → צילום אמיתי לפי `visual-check`, אימות דרך `gemini_task.py -f` (**לא לקרוא PNG לצ'אט**).
3. תיעוד: מלכודת חדשה → `manhal-haluka/references/pitfalls.md`; כלל שנלמד → הסקיל התחומי; שינוי התנהגות →
   `CLAUDE.md`; סטטוס וממצאים פתוחים → `NEXT_TASK.md`.
4. תוקן משהו → שחרור לפי `manhal-haluka` (bump גרסה → build → commit/push → release, **בלי קרדיט Claude**).
   לא נמצא כלום → לא משחררים; אם נוספו בדיקות — commit בלבד.
5. סיכום קצר ליהודה בעברית פשוטה: מה נבדק, **מה היה יכול לקרות לו בפועל** בכל באג, מה תוקן, ומה נשאר לשאלה.
