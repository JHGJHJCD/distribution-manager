# מודול API — פירוט מלא (נספח ל-SKILL.md)

כל הטבלאות והדוגמאות המפורטות שנאספו מהמקורות ב-01/09/2026.
מקור מרכזי: f2 post/76 (topic/56). מקורות נוספים מצוינים ליד כל סעיף.

## 1. איסוף קלט מהמתקשר — `api_NNN=` (וגם החלק השני של `read=`)

פורמט כללי: `api_NNN=שם_פרמטר,שימוש_בערך_קיים,<מצב>,...`
המספור `NNN` תלת-ספרתי (000, 001...); הערכים שנאספים מצורפים לבקשה הבאה
לשרת בשם שנתת. השדה השני (`yes`/`no`) קובע אם ערך שכבר נאסף באותה שיחה
ישמש שוב בלי לשאול מחדש.

המצב נקבע לפי השדה השלישי: מספר = הקשות · `record` = הקלטה · `voice` = זיהוי דיבור.

### 1א. הקשות (tap)

`api_000=ID,yes,5,4,50,Number,yes,no,*/,`

| # | שדה | ברירת מחדל / הערות |
|---|---|---|
| 1 | שם הפרמטר | |
| 2 | שימוש בערך קיים | yes/no |
| 3 | מקסימום ספרות | |
| 4 | מינימום ספרות | 1 |
| 5 | timeout להקשה (שניות) | 7 |
| 6 | סוג הקראה חוזרת (echo) | `Number` / `Digits` / `Price` / `Time` / `Date` / `HebrewDate` / `TeudatZehut` / `Phone` / `Alpha` / `HebrewKeyboard` / `EnglishKeyboard` / `GetMail` / `EmailKeyboard` / `DigitsKeyboard` / `File` / `TTS` |
| 7 | חסימת כוכבית | yes/no |
| 8 | חסימת ערך אפס | yes/no |
| 9 | החלפת תווים | למשל `*/` = כוכבית מוחלפת בלוכסן |
| 10 | ספרות מותרות | למשל `11.12.13.14` או `*#123456` |
| 11 | מספר ניסיונות לפני "ריק" | 1 |
| 12 | לאפשר ריק | `Ok` = מותר בלי אישור |
| 13 | טקסט לערך ריק | `None` |
| 14 | נעילת סוג מקלדת | `InsertLettersTypeChangeNo` |
| 15 | לדרוש אישור הקשה | ברירת מחדל yes; `no` = בלי שלב אישור |

### 1ב. הקלטה (record)

`api_007=ZAW,yes,record,/1/2,file_name,no,yes,yes`

| # | שדה | הערות |
|---|---|---|
| 4 | תיקיית שמירה | חייבת להתחיל ב-`/` |
| 5 | שם קובץ | ברירת מחדל: מספור אוטומטי |
| 6 | תפריט אישור אחרי ההקלטה | `no` = אישור אוטומטי |
| 7 | לשמור גם בניתוק באמצע | yes/no |
| 8 | צירוף לקובץ קיים (append) | yes/no |
| 9–10 | משך מינימום/מקסימום (שניות) | |

הודעת המערכת לפני הקלטה: M1012. כיבוי הביפ: `api_record_beep=no`.

### 1ג. זיהוי דיבור (voice)

`api_004=CCC,yes,voice`

| # | שדה | הערות |
|---|---|---|
| 4 | שפה | ברירת מחדל עברית |
| 5 | לאפשר גם הקשות | yes/no |
| 6 | מקסימום הקשות | |
| 7 | מנוע | ריק = רגיל; `record` = מבוסס-הקלטה בלבד |
| 8 | timeout שקט (שניות) | |
| 9 | משך הקלטה מקסימלי | |

עזרים: קובץ `NNN.ini` בשלוחה עם ביטויים צפויים (שורה לשורה) משפר את הדיוק ·
`api_say_tts=no` מדלג על הקראת מה-שזוהה · `api_voice_ask_ok=yes` דורש אישור
מפורש · `api_save_file=yes` שומר את ההקלטה.

## 2. `read=` — התחביר המלא

`read=<הודעה בתחביר id_list_message>=<פרמטרי קלט כמו api_NNN>`

דוגמאות מהמקורות:

```
read=f-prompt.txt=ParamName,yes,8,4,7,Number,yes,no,*/,
read=m-1800=password,yes,,,,No,          ← מ-f2 topic/13531 (שדות ריקים = ברירות מחדל)
read=t-ברוכים הבאים...=Num_Stop,no,,,,No,,No,*/,,,   ← מ-f2 topic/11191
```

מגבלות (f2 post/76): `read` אחד לכל תשובה; אי-אפשר לשרשר אליו עם `&`;
אין לשלוח שמות פרמטרים כפולים.

### תבנית "רשימה אינטראקטיבית" (f2 topic/11191)

`id_list_message` לבדו משמיע רשימה סטטית. כדי לדפדף (1=בחר, 2=הבא, 3=הקודם)
הדפוס המקובל: לולאה בצד השרת — כל סיבוב מחזיר `read=` שמשמיע את הפריט הנוכחי
ואוסף הקשה אחת (מקס' ספרה אחת, timeout קצר, ריק-מותר), והשרת מנהל את האינדקס
לפי `ApiCallId`. בפורום ממליצים על Node.js עם הספרייה הקהילתית
**yemot-router2** (github.com/ShlomoCode/yemot-router2) שממדלת בדיוק את
המודול הזה (`call.read(...)` וכו') — ⚠ ספרייה קהילתית, לא של ימות.

## 3. סוגי השמעה — הטבלה המלאה (`id_list_message`)

פריטים מופרדים בנקודה: `id_list_message=f-file.t-שלום.m-1001`

| קידומת | משמעות |
|---|---|
| `f-` | קובץ שמע (נטען מהשלוחה או מ-`api_dir`) |
| `t-` | טקסט ב-TTS |
| `m-` | הודעת מערכת לפי מספר (M-xxxx) |
| `d-` | הקראת ספרות אחת-אחת |
| `n-` | הקראת מספר שלם |
| `a-` | הקראת אותיות |
| `s-` | קובץ ‎.tts |
| `z-` | זמן (פורמט זמנים) |
| `date-` | תאריך לועזי |
| `dateH-` | תאריך עברי |
| `g-` | מעבר לשלוחה — עוצר את שרשרת ההשמעה; `g-hangup` = ניתוק |

## 4. דוגמת צד-שרת מלאה מהפורום (f2 topic/13531)

PHP אמיתי מהשטח — שלוחת API שמזהה חוסר בפרמטרים, מבקשת אותם ב-`read=`,
קוראת ל-API החיצוני של ימות (UploadTextFile) מתוך השרת, ומקריאה תוצאה
(הקוד כפי שפורסם, כולל שגיאות-כתיב של הכותב — לתבנית בלבד, לא להריץ כמו-שהוא):

```php
<?php
$ApiDID=$_GET['ApiDID'];
$password=$_GET['password'];
$k=$_GET['k'];
$ApiEnterID=$_GET['ApiEnterID'];
if($ApiDID== null){print "id_list_message=g-hangup"; exit();}
elseif($password == null){print "read=m-1800=password,yes,,,,No,"; exit();}
$url = json_decode(file_get_contents(
  "https://www.call2all.co.il/ym/api/UploadTextFile?token={$did}:{$password}"
  ."&what=Points.ini/points_total.ini&contents=..."), true);
$status = $url['responseStatus'];
if($status == "OK"){
  print "id_list_message=כמות הנקודות שקיבלתם היא $k2."; exit();
} else {
  print "id_list_message=m-1080 &go_to_folder=hangup"; exit();
}
?>
```

מה לומדים מהדוגמה: (א) בדיקת כל פרמטר ו-`read=` להשלמתו — כך בונים "טופס"
רב-שלבי על כתובת אחת; (ב) שילוב מודול-API עם ה-API החיצוני מתוך השרת
(וכך גם f2 topic/14020 — "hello world": `echo "id_list_message=t-שלום עולם";`);
(ג) `g-hangup` בתוך id_list_message ו-`go_to_folder=hangup` — שתי דרכים לנתק.

## 5. יומן, וובהוק שגיאות ותווים מוחלפים (f2 post/76)

- יומן: `Log/LogApi.ymgr` בשורש. כיבוי גורף: `api_log=no`; כיבוי לתשובה
  בודדת: להקדים `api_log_no&` לתשובה.
- החלפות ברישום: `=`→`^` · `&`→`*` · `,` בתשובות→`^`.
- וובהוק שגיאת-קובץ (`api_send_webhook_error_link=`) — גוף לדוגמה:

```json
{ "Action": "id list message type 'f'", "FilePath": "/000",
  "Status": "Error", "Message": "file audio not found" }
```

## 6. שרשור פעולות (f2 post/76)

- בתשובת השרת: `id_list_message=t-הודעה&routing_yemot=0773137770`
- בצד ההגדרות: `api_answer_OK=id_list_message=t-הודעה` ואז
  `api_answer_OK_1=routing_yemot=0773137770` — מספור רציף 1,2,3 בלי חורים.
- `read` — לא ניתן לשרשור (ראו סעיף 2).
