# מודול API בשלוחה — הקו מדבר עם השרת שלך

מנגנון מובנה של ימות המשיח: שלוחה מסוג `api` שולחת בכל כניסת-מתקשר בקשת HTTP
לכתובת שהגדרת, עם פרטי השיחה (טלפון, שלוחה, הקשות...), והשרת מחזיר **טקסט
פשוט** עם פקודות — השמע הודעה, נווט לשלוחה, בקש הקשה נוספת ושלח שוב, נתק.
כך בונים IVR דינמי שכל הלוגיקה שלו בקוד שלך.

**לא לבלבל עם ה-API החיצוני (גישת מפתחים):** שם *אתה* פונה אל
`call2all.co.il/ym/api` כדי לנהל את המערכת (זה מה שמתועד בסקיל הענן
`anthropic-skills:yemot-hamashiach` וב-`utils/yemot.py`). כאן *הקו* פונה
אל השרת *שלך* בזמן שיחה חיה. התיעוד הרשמי מדגיש: "אין קשר בין API זה
למודול ה-API" (f2 post/75). אפשר לשלב: השרת שמקבל את הבקשה מהשלוחה יכול
בעצמו לקרוא ל-API החיצוני עם טוקן (f2 topic/14020) — כך בדיוק עובדת שלוחה
555/4 בקו שלנו.

מקור מרכזי: f2 post/76 (topic/56 — "מודול API: תקשור עם מחשבים וממשקי
נתונים חיצוניים"). פירוט מלא של פרמטרי הקלט, סוגי ההשמעה ודוגמאות קוד —
ב-`references/api-module-details.md`.

## 1. הגדרות ext.ini של השלוחה (f2 post/76)

| מפתח | ערכים | מה עושה |
|---|---|---|
| `type=api` | — | חובה: מגדיר את השלוחה כשלוחת API |
| `api_link=` | URL מלא | כתובת השרת. **בלעדיה** — הודעת שגיאה M1609 ("לא הוגדר קישור") והמתקשר יוצא |
| `api_url_post=yes` | ברירת מחדל GET | שליחת הפרמטרים ב-POST במקום GET |
| `api_dir=/5/6` | נתיב שלוחה | מאיפה לטעון קובצי השמעה (מתחיל ב-`/`, בלי `/` בסוף) |
| `api_add_0=foo=111` | מספור רציף מ-0 | פרמטרים קבועים שמצורפים לכל בקשה (כך מוטמע הטוקן ב-555/4) |
| `api_NNN=` | ראו references | איסוף קלט מהמתקשר (הקשות/הקלטה/זיהוי דיבור) לפני השליחה |
| `api_hangup_link=` | URL | כתובת נפרדת לדיווח ניתוק (ברירת מחדל: אותו `api_link`) |
| `api_hangup_send=no` | ברירת מחדל yes | לא לשלוח בקשה כשהמתקשר מנתק |
| `api_end_goto=/5/8` | נתיב | לאן להמשיך כשה-API מסיים (ברירת מחדל: חזרה לשלוחה הקודמת) |
| `api_wait_answer_music_on_hold=yes` | — | מוזיקת המתנה בזמן שהשרת "חושב" (+גרסאות `_different`/`_continue_all_sends`) |
| `say_api_answer=yes` | — | תשובה פשוטה מהשרת (כמו `OK`) מוקראת ב-TTS אם אין קובץ תואם |
| `api_answer_XXX=` | פעולה | מיפוי תשובה→פעולה בצד ההגדרות, למשל `api_answer_OK=go_to_folder=3` (שרשור: `api_answer_OK_1=` וכו') |
| `api_log=no` | ברירת מחדל yes | כיבוי רישום ל-`Log/LogApi.ymgr` |
| `api_add_replace_space=yes` | — | רווחים בערכים נשלחים כ-`+` (עברית ממילא עוברת URL-encoded) |
| `api_send_webhook_error_link=` | URL | קבלת webhook (JSON) כשקובץ השמעה שהשרת ביקש לא נמצא |

כיבוי פרמטרים אוטומטיים: `api_call_id_send=no`, `api_phone_send=no`,
`api_did_send=no`, `api_extension_send=no`, `api_enter_id_send=no`,
`api_enter_id_name_send=no`, `api_time_send=no`.
תוספת: `api_add_directed_phone=yes` ⇒ פרמטר `ReferredFrom` (מי העביר את השיחה).

⚠ השם `api_url_link` צץ בפוסטים ישנים בפורום, אבל בתיעוד הרשמי (post/76)
ובכל הדוגמאות החיות המפתח הוא **`api_link`** — להשתמש בו. (טרם אומת אם
`api_url_link` בכלל נתמך כ-alias.)

## 2. מה השרת מקבל בכל בקשה (f2 post/76)

| פרמטר | תוכן |
|---|---|
| `ApiCallId` | מזהה ייחודי של השיחה (לזיהוי רצף בקשות מאותה שיחה!) |
| `ApiPhone` | מספר המתקשר |
| `ApiDID` | המספר הראשי של המערכת |
| `ApiRealDID` | המספר שחויג בפועל (כשיש כמה DID) |
| `ApiExtension` | נתיב השלוחה הנוכחית |
| `ApiEnterID` / `ApiEnterIDName` | סוג+מספר הזיהוי והשם — אם המתקשר עבר כניסה מזוהה (סקיל yemot-enter-id) |
| `ApiTime` | חותם זמן Unix (שניות) |
| `<שם>=<ערך>` | כל `api_add_N` קבוע + כל קלט שנאסף (`api_NNN` או `read=`) |

בניתוק נשלחת בקשה נוספת עם `hangup=yes` ו-`ApiHangupExtension=/3`
(השלוחה שבה הסתיימה השיחה). User-Agent של הבקשות: `yemot-core-api/1.0`.

## 3. פורמט התשובה — טקסט פשוט בלבד!

השרת חייב להחזיר **plain text** — לא JSON ולא HTML. תשובה לא-תקינה ⇒
M1607 "אין מענה משרת ה-API" והמתקשר יוצא מהשלוחה (f2 post/76).

פקודות שאפשר להחזיר (שרשור עם `&` ביניהן):

| פקודה | דוגמה | מה עושה |
|---|---|---|
| `go_to_folder=` | `go_to_folder=/3` · `go_to_folder=hangup` | ניווט לשלוחה / ניתוק |
| `id_list_message=` | `id_list_message=t-שלום עולם.n-45.m-1001` | השמעה: פריטים מופרדים בנקודה, כל פריט `סוג-ערך` |
| `go_to_folder_and_play=` | `go_to_folder_and_play=/1/5,005,1001` | ניווט + השמעה מקובץ/נקודה מסוימת |
| `read=` | `read=t-הקש קוד=code,yes,4,4,7,Number,yes,no` | השמע הודעה, אסוף קלט, **ושלח את הבקשה שוב** עם הפרמטר החדש |
| `music_on_hold=` | `music_on_hold=music_name,30,no_return` | מוזיקת המתנה |
| `routing=` | `routing=0581234567.0533137770,1` | ניתוב לטלפון ישראלי (כמה מספרים בנקודות) |
| `routing_yemot=` | `routing_yemot=0773137770` | ניתוב למערכת ימות אחרת |
| `credit_card=` | `credit_card=pelecard,100,...` | סליקת אשראי בתוך השיחה |
| `api_log_no` | `api_log_no&go_to_folder=/5/8` | אל תרשום את התשובה הזו ביומן |

סוגי השמעה ב-`id_list_message` (וגם בחלק-ההודעה של `read=`):
`t-` טקסט (TTS) · `f-` קובץ · `m-` הודעת מערכת לפי מספר · `d-` הקראת ספרות ·
`n-` הקראת מספר · `a-` אותיות · `s-` קובץ ‎.tts · `z-` זמן · `date-` תאריך
לועזי · `dateH-` תאריך עברי · `g-` מעבר לשלוחה (כולל `g-hangup` לניתוק —
נראה חי בדוגמת f2 topic/13531).

מגבלות `read=` (f2 post/76): פקודה **אחת** לכל תשובה, ואי-אפשר לשרשר אליה
פקודות נוספות. פרמטרי הקלט שאחרי ה-`=` השני זהים לפורמט `api_NNN`
(שלושה מצבים: הקשות / `record` / `voice` — הטבלה המלאה ב-references).

**תשובות פשוטות:** אפשר גם להחזיר סתם `OK` או `Error1` — המערכת תחפש קובץ
`OK.wav` בשלוחה להשמעה, ואז תפעיל את `api_answer_OK=` מההגדרות. נוח כשרוצים
שהלוגיקה "מה עושים" תישאר ב-ext.ini והשרת רק מחליט.

## 4. דוגמה מוכנה להדבקה

ext.ini של השלוחה:

```ini
type=api
api_link=https://example.com/YemotApi
api_url_post=yes
api_wait_answer_music_on_hold=yes
```

צד-שרת מינימלי — PHP כפי שמופיע בתיעוד (f2 topic/14020):

```php
<?php
echo "id_list_message=t-שלום עולם";
?>
```

אותו דבר ב-Python (תרגום ישיר; Flask):

```python
from flask import Flask, request
app = Flask(__name__)

@app.route("/YemotApi", methods=["GET", "POST"])
def yemot():
    vals = request.values          # GET או POST — אותו דבר
    phone = vals.get("ApiPhone", "")
    code  = vals.get("code")
    if code is None:               # סיבוב ראשון — לבקש קלט ולחזור אלינו
        return "read=t-נא הקש קוד בן 4 ספרות=code,yes,4,4,7,Number,yes,no"
    if code == "1234":
        return "id_list_message=t-הקוד נכון.&go_to_folder=/3"
    return "id_list_message=t-קוד שגוי.&go_to_folder=hangup"
```

שימו לב לתבנית: **אותה כתובת נקראת שוב ושוב באותה שיחה** — כל `read=` מחזיר
את המתקשר אליך עם הפרמטר החדש. מזהים את השיחה לפי `ApiCallId` (אין session
אחר). דוגמה חיה מלאה יותר (כולל קריאה ל-API החיצוני מתוך השרת) —
ב-references.

## 5. בדיקת כניסה מול שרת — check_api (f2 post/58432)

שני מנגנונים נפרדים מהמודול המלא, כשרוצים רק "לשאול את השרת אם לתת להיכנס":

- **שלוחת ניתוב לפי API:** `type=call_api_verification` + `call_api_link=`
  (+`call_api_type=POST`). השרת מקבל `ApiDID`/`ApiPhone`/`ApiExtension`
  ומחזיר ערך; מנתבים עם `call_api_answer_OK=/1`, `call_api_answer_ERROR=/7`,
  או שהשרת מחזיר `GOTO=XX` דינמי.
- **בדיקה על כל כניסה לשלוחה רגילה:** `check_api=yes` + `api_link=` +
  `check_api_every_entry=yes`. תשובות: `OK` = ממשיכים · `NO` = יציאה עם
  M1102 (אין הרשאה) · `Out` = יציאה שקטה. ניתוב: `api_goto=/1`,
  `api_error_goto=/2`.

## 6. מלכודות (מהמקורות בלבד)

- **טקסט פשוט בלבד** — JSON/HTML/תגית מיותרת בתשובה ⇒ M1607 והמתקשר עף.
  זו התקלה הנפוצה ביותר (f2 post/76).
- **עברית** — עוברת URL-encoded אוטומטית; רווחים אפשר כ-`+` עם
  `api_add_replace_space=yes`. להחזיר תשובות ב-UTF-8.
- **מספור רציף** — `api_add_N` מ-0 בלי חורים; שרשורי `api_answer_X_N`
  מ-1 בלי חורים. חור = השאר לא נקרא (f2 post/76).
- **אין הגדרת timeout מתועדת מול השרת** — לא נמצא במקורות מפתח בשם
  `api_time_out` וכד'; ⚠ טרם אומת כמה זמן המערכת מחכה. ההגנה בפועל: שרת
  מהיר + `api_wait_answer_music_on_hold=yes`. (ה-timeout שכן קיים הוא של
  *קלט המתקשר*, פרמטר 5 בהגדרת `api_NNN`/`read=`.)
- **יומן `Log/LogApi.ymgr`** — התווים `=`,`&`,`,` מוחלפים ברישום ל-`^`/`*`/`^`.
  אל תנסה לפרסר את היומן כאילו הוא התשובה המקורית. שורות `Folder#1` ביומן
  של הקו שלנו = שיחות שהסתיימו בשלוחה 1 (`ApiHangupExtension`), לא hook של
  שלוחה 1 (נלמד בתחקיר 01/09/2026, סקיל yemot-line-knowledge).
- **קובץ השמעה חסר** (`f-` שלא קיים) — לא שגיאה קולית ברורה; אפשר לקבל
  דיווח JSON עם `api_send_webhook_error_link=` (f2 post/76).
- **שורת `type=` אחת בלבד** פעילה בכל ext.ini — אל תוסיף `type=api` לשלוחה
  שכבר יש לה type (מלכודת כללית, סקיל yemot-line-knowledge).

## 7. קשר לקו של קופה של צדקה הר יונה

בקו **כבר יש** שלוחות API חיות (פירוט וסודות — סקיל yemot-line-knowledge):

- שלוחות `10`/`12`/`13` (+`10/999`) → שרת PHP חיצוני של מפתח פרטי
  (הכתובת — בסקיל yemot-line-knowledge; תרומות/רישום/סקרים — **לתאם איתו
  לפני כל שינוי**).
- שלוחה `555/4` → Cloud Run (`kupaUpdateSumWeek`) עם
  `api_add_1=apiToken=<מספר>:<סיסמה>` — הטוקן של הקו מוטמע ב-ext.ini גלוי;
  שינוי סיסמת המערכת שובר אותה.

**פוטנציאל עתידי לאפליקציית מנהל חלוקה:** שלוחת API שפונה לשרת קטן שלנו —
למשל מקבל מתקשר, מזוהה לפי `ApiPhone` מול ה-DB, מקיש 7 לאישור הגעה והאישור
נרשם ישירות ב-DB (במקום מעקב הקמפיינים הנוכחי). דורש שרת נגיש מהאינטרנט
(לאפליקציה אין כזה כיום — Cloud Run/דומה), ⚠ טרם נוסה.
